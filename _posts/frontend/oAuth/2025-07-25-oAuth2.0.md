oauth 인증 단계를 정리해 봤어. 맞니?

1) Resource Server에 Client에 대한 정보를 등록한다.
   등록 사항 : 시스템 URL, Authorized redirect URIs

2) Client에 ClientID/Secret 정보를 환경변수화 함.

3) Resource Owner가 Client에 접속, Client는 Login을 위한 정보를 Owner에 제공
  https://resource.server/?client_id=1&scope=B,C&redirect_uri=https://client/callback 
  
4) Resource Owner의 Browser는 받은 정보로  Resource Server로 접속하게됨
5) Resource Server는 ClientID와 Redirect URL을 비교하여 같은지 판단 후
    Resource Owner에서 Login 허락 화면을 보냄.(이후, Scope도 동일하게 진행)
    - ClientID 1번에게 로그인 및 권한을 허락함.

6) Resource Server는 Owner가 권한을 허락했으니, 승인해줘야 함.
   - 임시 비밀번호인 Authorization code를 부여, Resource Owner에게 전달함.
     https://client/callback?code=3(Redirect 정보)

7) Resource Owner의 Browser는 Redirect 정보대로 Client에 접속함.(Redirection)
   - Client는 Authorization code:3을 알게 됨.

8) Client는 직접 Resource Server에 접속하게 됨
   - ClientID/Secret, Authorization code
   https://resource.server/token?grant_type=authorization_code&code=3&
   redirect_uri=https://client/callback&client_id=1&client_secret=2
   
9) Resource Server는 ClientID/Secret, Authorization code, Redirect URL 모두 일치하면
    Authorization code 삭제, AccessToken 발급
    Client에 전달하여, Client도 AccessToken 확보함.
